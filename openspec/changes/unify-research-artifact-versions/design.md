## Context

Research outputs are heterogeneous, but their storage invariants are shared: one stable identity, append-only versions, verified bytes, exact dependency references, and recovery without rewriting history. Scientific meaning is not a storage invariant. Claim validity, evidence level, statistical correctness, and human approval therefore remain in their owning domains.

## Decisions

### One version owner

`@sciforge/domain-artifact-versions` owns `ResearchArtifactRecordV1`, `ArtifactVersionV1`, `ArtifactVersionRefV1`, content-addressed snapshot objects, current pointers, structural dependencies, lifecycle events, restore, and bundle verification. No consumer may retain a second live Registry, current pointer, or compatibility write path.

### Atomic semantic commits over CAS bytes

`artifact-versions.commit` is the only formal write entry. A transaction uses an idempotency key and optimistic expected-current values, can commit several candidate artifacts atomically, and stores bytes once by SHA-256. Explicit save, rerun, restore, and publish create semantic versions even when bytes deduplicate; passive observation of identical bytes is idempotent.

### Evidence references fixed versions

SourceAnchor and Run records pin full `ArtifactVersionRefV1` values. Evidence Snapshots never resolve `latest` and remain owned by Evidence DAG. A durable lifecycle consumer persists workspace cursors and receipts, advances a cursor only after every affected thread has been durably enqueued, and creates a new snapshot projection instead of mutating an old snapshot.

### Plotting is a complete producer

A formal plot commit contains derived data, `ScientificPlotRecipeV1`, PNG, render manifest, and log with explicit dependencies and Evidence lineage. Statistics and transformations are explicit, duplicate aggregation and significance decoration cannot be silent, and rerun reads only pinned CAS versions. Missing or mismatched inputs create a provenance breakpoint and fail closed.

### Review appends, never overwrites

Visual Review stages bytes bound to a full version ref. Accept revalidates the current version and appends a new version with a `reviewed-from` dependency; reject leaves current unchanged. A durable receipt makes post-commit activation recoverable and idempotent.

### Portable verification

Bundle export contains only requested exact versions plus transitive exact dependencies and their CAS objects. Import verifies the manifest and object digests before an atomic install. A clean workspace can import a plot bundle and rerun using only version refs.

### Semantic export ownership

PROV, RO-Crate, DataCite, audit, and reproduction reports are generated by Evidence DAG against a caller-supplied fixed snapshot digest. The files are committed atomically through Artifact Versions, carry the snapshot digest in metadata, and depend on all exact Artifact Versions referenced by that snapshot.

## Migration

1. Install the Artifact Versions owner and migrate historical Evidence Registry records once while preserving Artifact ID, Version ID, digest, and snapshot bytes.
2. Switch Evidence reads and writes to the public capability contracts, preserve old Snapshot bytes/digests, then delete the live Registry write entry.
3. Route Scientific Plotting and Visual Review through the capability broker and remove parallel business MCP/IPC paths.
4. Regenerate installed-domain composition and validate source and packaged paths.

## Non-goals

- Multi-user content merging.
- Moving Claim, Run, SourceAnchor, assessment, Evidence Snapshot, or L0-L4 policy into the version store.
- Direct parsing of every scientific binary format inside plotting.
- Treating a pending provenance update or unverified significance annotation as reproducibility-complete.
