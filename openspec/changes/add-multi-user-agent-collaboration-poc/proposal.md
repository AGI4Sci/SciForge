# 变更提案：多用户端—云 Agent 协同 PoC

## 为什么要做

SciForge 已经可以在一台电脑或服务器上运行 Agent、使用本地工具并完成科研工作，但多个用户的
SciForge 之间还不能围绕同一个复杂目标可靠协作。现实中的协作大量依赖群聊、反复同步和会议：
每个人先人工整理自己的状态，再由负责人拼接信息，最后把许多机器本来可以解决的问题带到真人
会议中。

本 PoC 希望验证一种更低成本的协作方式：所有具备智能和执行能力的节点都是普通 SciForge；
云端不运行特殊的“超级 Agent”，只保存长期记忆、必要项目信息，并提供身份、任务信箱、消息
中转和最小并发控制；手机端只作为人类 IM，接收真正需要本人处理的问题、审批和结果。

项目发起人选择一台 SciForge 作为协调者。协调者把目标拆成任务，通过云端信箱分发给其他用户
或机器上的 SciForge，汇总结果，并只把无法可靠自动解决的内容升级给真人。这样既能保持端侧
智能和数据边界，又能避免多个 Agent 自由群聊造成的任务重复和项目状态混乱。

## 变更内容

- 增加一个不含 LLM 的云端协作内核，负责用户和 Agent 身份、Project 账本、长期记忆、任务
  信箱、WebSocket 消息、离线补发、Coordinator 唯一性、Task 版本和幂等。
- 把每个桌面、服务器或云机器上的 SciForge 注册为独立 Agent 节点，声明稳定身份、所有者、
  节点类型、能力、在线状态和最后心跳。
- 每个 Project 同时只允许一个活跃协调者 SciForge。只有协调者可以修改全局计划、创建任务、
  接受最终结果和提交项目总结。
- 采用星形协作：工作 Agent 只接受协调者分配的 Task，并提交状态、问题和结果；工作 Agent 不
  直接修改全局计划，也不彼此自由广播。
- 定义最小 Task 状态和结构化消息，使云端能够拒绝重复接受、过期结果、越权状态修改和错误
  执行者提交。
- 云端长期记忆分为用户私有记忆和 Project 共享记忆；本地文件、凭据、私有数据和临时上下文
  默认留在具体 SciForge 节点。
- 增加响应式手机 IM，只展示真人问题、审批、重要摘要和最终结果，不展示 Agent 工具日志或
  内部协作噪声。
- 以“先由 Agent 解决会议议题”为首个端到端场景：协调者自动收集信息、分派分析、关闭机器可
  解决的问题，只为剩余问题生成最小真人参与请求。
- 首期保持一个云端服务、一个 PostgreSQL 和一个 WebSocket 通道，不引入微服务、Kafka、
  Redis、向量数据库、原生手机 App、资源市场、GPU 租约或机构联邦。

## 新增能力

- `cloud-collaboration-kernel`：云端身份、Project/Task 账本、长期记忆、Agent 信箱、事件中转、
  离线恢复和最小并发控制。
- `sciforge-agent-node`：SciForge 节点注册、能力声明、任务接收、AgentRuntime 执行、状态回传
  和断线重连。
- `project-agent-collaboration`：单协调者计划、任务分解、星形分发、结果汇总、真人升级和项目
  完成语义。
- `human-im`：手机/网页上的真人问题、审批、摘要、回答和完成通知。

## 修改的现有能力

- `agent-runtime`：工作任务继续通过现有 runtime-neutral Host 执行；PoC 不新增 SciForge 自定义
  模型 Runtime，也不让云端直接调用 Codex/Claude 私有协议。
- `capability-broker`：本地文件、命令和外部写入继续走已有能力、权限和审计路径，远端任务不能
  绕过本地审批。
- `multi-agent`：继续处理一台 SciForge 内部的子 Agent；跨用户协作由新的 Project/Task 协议
  负责，不扩展现有 parent-turn child-run 作为云端任务状态。
- `shared-memory`：用户偏好可以进入用户私有命名空间；Project 正式状态和结果进入 Project
  Memory，不能混成所有用户共享的自由文本记忆库。

## 影响与边界

- 主要新增一个端—云协作领域 package、一个最小云端服务、SciForge 节点连接器、Project
  协调工作流和响应式手机页面。
- PoC 只传输文本任务、结构化状态、结果摘要和必要项目记忆；不自动上传工作区、原始数据、
  凭据或完整 Agent 对话。
- Coordinator 离线时首期允许 Project 暂停，并支持用户手动转交协调权；不实现自动选主。
- 首期不接入日历和视频会议。系统只生成“已自动解决、需要单人确认、确实需要多人讨论”的
  会议准备结果。
- 首期不建设机构 Site Node、VPN、GPU 共享、计费、信誉、Agent 市场、端到端加密同步、P2P
  通信和多云部署。
