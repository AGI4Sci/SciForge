# @sciforge/sci-modality-router

A SciForge **Model-Router-managed worker** (`packages/workers/sci-modality-router`) — the
scientific-data analogue of a vision translator. It translates a **non-text scientific input**
(protein sequence or 3D structure, small molecule, single-cell expression) into
**natural-language evidence** through the local SciForge Model Router boundary, so a text-only
main agent can consume the data as text.

- **Translate-only.** Each expert describes what its model generated about the input. It
  never reasons, answers the user, gives advice, draws conclusions, or claims task
  completion. Reasoning stays with the main agent.
- **Native-to-text model boundary.** Every translation must be natural-language text
  generated by a Model-Router-managed domain translator on a real forward pass, never a prompted
  general LLM substitute. A local expert runtime stamps a `system_fingerprint`
  (`expert@device <ms>ms`) on every response.
- **Self-contained.** Zero runtime npm dependencies (Node 20+ `node:http` + `fetch`). The
  TypeScript service (`src/`) and the Python local expert runtime (`provider/`) live in this one folder.
- **HTTP service, not an MCP tool.** It returns a stable `ServiceResult` envelope and is invoked
  by the host during input pre-extraction (a deterministic transform), not chosen by an agent.

## Architecture (Model Router owned)

```
GUI/local runtime/Codex/Claude input_object ref  ──>  Model Router  ──HTTP──>  @sciforge/sci-modality-router (this, TS)  ──local /v1──>  Model Router expert boundary
       workspace file ref              gating + fallback       ServiceResult contract + retry                         local expert runtime
```

- **This worker** owns the `ServiceResult` contract, modality detection, and robustness.
- **No direct provider bypass.** The TS worker only accepts a local
  `SCIFORGE_MODEL_ROUTER_BASE_URL` ending in `/v1` (`127.0.0.1`, `localhost`, or `[::1]`) plus
  the local Model Router runtime key. Legacy `EXPERT_PROVIDER_*` env vars are rejected.
- **Model Router** (`@sciforge/model-router`) is the only in-repo caller. Runtimes pass structured
  workspace file refs; they do not read `SCIFORGE_SCIMODALITY_SERVICE_URL` or call this service
  directly. Model Router reads it via that env var (see `packages/workers/model-router/src/router.ts`).
- **`provider/`** is an optional self-hosting reference for operators who have independently
  verified model licenses. It is a local expert runtime, not an external LLM provider, and is
  disabled by default until `SCIFORGE_ENABLE_LOCAL_EXPERT_PROVIDER=1` plus external model paths
  are supplied.

## The four modalities

Every expert is a genuine domain model whose **native output is text** — there are no general-LLM
interpreters and nothing is composed from hand-rolled numeric summaries. We only support modalities
for which a Model-Router-managed native-to-text model can be attached cleanly after license review.

| Modality | Expert id | Model (native text output) | Notes |
|---|---|---|---|
| `protein` | `esm2text-protein` | Esm2Text-Base (ESM-2 + GPT, sequence-only) | sequence → function description |
| `protein_structure` | `prot2text-structure` | Prot2Text-Large (ESM-2 + RGCN + GPT-2) | 3D structure (PDB) → function description; isolated `p2t` micro-service (graphein + DSSP) |
| `molecule` | `biot5-molecule` | BioT5+ (T5, SELFIES→caption) | SMILES → caption; ChEBI-20 captioning SOTA among open checkpoints |
| `single_cell` | `c2s-singlecell` | C2S-Scale-Gemma-2 (Cell2Sentence) | scRNA-seq "cell sentence" → cell-type text |

**Deliberately not supported** (no clean native-to-text model selected for this worker): `nucleotide`
(ChatNT is non-commercial; genomic foundation models emit task tokens, not text), `spectrometry`
(MS models output structures/SMILES, not text), `spatial` (no open spatial→text model). These are
rejected at detection rather than translated by a stand-in LLM.

The desktop/commercial package does not distribute model weights, download commands, or direct
provider connections. Operators may explicitly enable the local reference expert runtime after
license review and register that capability behind the local Model Router.

## Run

The local expert runtime is optional and operator-managed. The TS worker itself only calls a
local SciForge Model Router `/v1` endpoint. See [`DEPLOYMENT.md`](DEPLOYMENT.md) for the full
self-hosting setup.

```bash
# 1) Optional local expert runtime (on an operator-managed GPU server, after license review)
export SCIFORGE_ENABLE_LOCAL_EXPERT_PROVIDER=1
export EXPERT_TRANSLATOR_RUNTIME_TOKEN=replace-with-local-expert-runtime-token
export EXPERT_MODEL_DIR=/absolute/path/to/licensed/expert-models
export PROT2TEXT_MODEL_DIR=/absolute/path/to/licensed/prot2text-checkpoint
cd provider && bash start.sh   # FastAPI on :8001
bash provider/start_prot2text.sh

# 2) This worker (from the SciForge repo root). It reads only the local Model Router URL/key.
export SCIFORGE_MODEL_ROUTER_BASE_URL=http://127.0.0.1:3892/v1
export SCIFORGE_MODEL_ROUTER_RUNTIME_API_KEY=replace-with-local-model-router-runtime-token
npm --workspace @sciforge/sci-modality-router run start         # http://127.0.0.1:3898
```

When SciForge runs on a different machine than the local expert runtime, expose the runtime only
over a stable private connection to the local Model Router. Do not point this worker at a remote
LLM/provider URL; its base URL must remain a local Model Router `/v1` endpoint. The commercial
package does not auto-wire this service; Model Router consumes it only when its service URL/token
are configured.

## API

```
GET  /health        -> { ok, service, checkedAt }
GET  /version       -> { service, version, provider: { kind, configured, expertCount }, modalities }
GET  /experts/status-> { ok, modelRouterReachable, experts: [{ modality, model, online }], checkedAt }
POST /modality/translate
```

Public diagnostics report local Model Router availability state, but never return its base URL
or runtime key. For `/experts/status`, `online` means the local Model Router boundary is
reachable; individual expert runtime weight loading remains behind that boundary.

`POST /modality/translate` request:

```jsonc
{
  "payload": "MKTAYIAKQR...",        // raw scientific text (FASTA / SMILES / matrix / PDB)
  "modality": "protein",             // optional — omit to auto-detect from payload
  "instruction": "what is this?",    // optional context (NOT a task to solve)
  "objectId": "upload-123",          // optional, echoed into provenance
  "requestId": "optional"
}
```

Response — `ServiceResult<ModalityTranslation>`:

```jsonc
{
  "ok": true,
  "summary": "[esm2text-protein] generated protein evidence; …",   // bounded preview
  "data": {
    "summary": "…full multi-line evidence from the model…",
    "modality": "protein",
    "model": "esm2text-protein",
    "modalitySource": "detected"
  },
  "provenance": { "serviceId": "sciforge.sci-modality-router", "operation": "modality_translate", "requestId": "…" }
}
```

Failures return `{ ok: false, error: { code, message, retryable }, provenance }` with codes
`INVALID_ARGUMENT` / `UNAUTHENTICATED` / `NOT_FOUND` / `RATE_LIMITED` / `TIMEOUT` / `UNAVAILABLE` / `INTERNAL_ERROR`.

## Robustness (lives here, not in the caller)

The main agent cannot read these modalities, so a raw-payload fallback is useless — this
worker is the authority on "keep trying until the expert answers". Each call retries transient
failures (timeout / 5xx / 429 / network) with exponential backoff; only auth (401/403) and an
unregistered-expert (404) stop it early, plus a caller disconnect. The HTTP caller (Model Router)
therefore stays a thin one-shot POST. Tunables (env):

| Var | Default | Meaning |
|---|---|---|
| `SCIFORGE_MODEL_ROUTER_BASE_URL` | _(required)_ | Local SciForge Model Router `/v1`, e.g. `http://127.0.0.1:3892/v1`. External hosts and legacy `EXPERT_PROVIDER_*` are rejected. |
| `SCIFORGE_MODEL_ROUTER_RUNTIME_API_KEY` | _(required)_ | Bearer token for the local Model Router runtime boundary. |
| `SCIMODALITY_MODEL_ROUTER_TIMEOUT_MS` | `180000` | Per-attempt timeout (model routing + inference can be slow). |
| `SCIMODALITY_MODEL_ROUTER_MAX_ATTEMPTS` | `6` | Total attempts before giving up. |
| `SCIMODALITY_MODEL_ROUTER_RETRY_BASE_MS` | `1500` | Exponential backoff base (capped at 15s). |
| `SCIMODALITY_ROUTER_HOST` | `127.0.0.1` | Bind host for this worker. |
| `SCIMODALITY_ROUTER_PORT` | `3898` | Bind port for this worker. |
| `SCIMODALITY_ROUTER_RUNTIME_TOKEN` | _(required)_ | Bearer token required by this worker's HTTP API. |

## How SciForge uses it

Model Router consumes this worker during input routing:

- GUI copies explicit scientific uploads into the workspace and passes a structured `input_object`
  ref through the runtime.
- Model Router protects a broad set of scientific extensions from raw-text fallback, but only
  allowlisted uploaded-file formats backed by a deployed expert are sent to this service: protein FASTA
  (`.fasta`, `.fa`, `.faa`), protein structure (`.pdb`, `.cif`, `.mmcif`), and molecule formats
  (`.smi`, `.smiles`). Generic `.txt`, `.csv`, and `.tsv` are not
  auto-routed to this service.
- Because `.fasta` and `.fa` can contain either nucleotide or protein sequences, Model Router
  performs conservative local content classification before selecting the protein expert. Pure
  DNA/RNA and nucleotide-ambiguous sequences fail closed; `.faa` is protein-specific.
- Protected formats without a registered native-to-text expert (for example `.vcf`, `.bed`,
  `.gff`, and `.mgf`) fail closed with `scientific_modality_unsupported`; neither their raw
  contents nor an auto-detection request is sent to the translator or text reasoner.
- When the Model Router profile has `translators.scientific` configured, Model Router reads the
  workspace file text, POSTs it here (`/modality/translate`), and injects the returned evidence
  into the text reasoner. The GUI sidecar and CLI can still use
  `SCIFORGE_SCIMODALITY_SERVICE_URL` / `SCIFORGE_SCIMODALITY_SERVICE_TOKEN` as deployment inputs
  to generate that profile role. When unset or unavailable, Model Router only falls back to
  readable raw text for low-risk, non-protected formats.

## Test

```bash
npm --workspace @sciforge/sci-modality-router run test       # stubbed local Model Router, no network, no GPU
npm --workspace @sciforge/sci-modality-router run typecheck
```

The real-model end-to-end proof (no cheating) lives in [`tests/e2e_real_models.py`](tests/e2e_real_models.py) —
it drives this worker through the local Model Router and checks the local expert runtime for real
model fingerprints and input-dependent generated text across all four modalities. (Any expert whose
weights are absent is skipped rather than failed, so it still passes on a partial deployment.)
