# `@sciforge/workspace-egress`

Workspace-scoped network egress policy and a loopback-only HTTP CONNECT relay.
It lets an offline remote workspace use either the user's local network path or
an already-authorized remote workspace (for example, an online CPU host used by
an offline GPU host).

## Ownership boundary

This worker owns:

- short-lived, workspace-scoped bearer leases;
- destination hostname and port allowlists;
- lease heartbeat, expiry, revocation, and route-loss handling;
- a CONNECT-only relay bound to a literal loopback IP;
- secret-safe public summaries and diagnostic redaction.

It does **not** own SSH, VPN, target discovery, host aliases, credentials, or
tunnel setup. Those remain in the host/domain integration and are supplied as
an opaque `WorkspaceEgressRouteResolver`. A resolved route exposes only an
opaque route ID and an `openTunnel` function.

The public route selection is the canonical
`WorkspaceNetworkEgressSelection` from
`@sciforge/domain-sdk/workspace-host`:

- `{ mode: "none" }`
- `{ mode: "local", allowlist }`
- `{ mode: "remote-target", authorizedSessionId, allowlist }`

`authorizedSessionId` refers to an already-authorized workspace-host session.
Raw SSH aliases and target IDs never enter the egress contract. The selection's
SDK-owned allowlist is the only allowlist: rules use exact lowercase hosts and
explicit ports, with no wildcard matching.

## Flow

1. The workspace host asks for a lease with its workspace ID and canonical
   selection; the worker derives policy from `selection.allowlist`.
2. The injected resolver materializes the selected route.
3. The worker returns a loopback CONNECT endpoint and a one-time bearer token.
4. Workspace processes use `Proxy-Authorization: Bearer <token>`.
5. The relay accepts only allowlisted `host:port` authorities.
6. Heartbeats renew the lease and probe the route. Expiry, revocation, or route
   loss closes active streams and invalidates the token.

The host integration must inject **only** the returned relay endpoint and lease
token into the remote workspace process. It must never serialize or forward the
selection, `authorizedSessionId`, resolver input, or resolved-route metadata to
that process. Those values stay in the trusted local control plane. The remote
process needs only a proxy URL plus its short-lived proxy credential.

`createWorkspaceEgressProcessProxyEnvironment({ endpoint, credential })`
produces uppercase and lowercase `HTTP_PROXY`, `HTTPS_PROXY`, and `ALL_PROXY`
variables for Codex and standard HTTPS clients. Its input schema is strict, so
passing a complete lease (which includes selection metadata) is rejected. The
relay accepts both direct Bearer proxy authorization and the fixed
`sciforge-lease:<token>` Basic form generated by standard proxy URL clients.
Both forms authorize the same scoped lease; Basic does not create a second
credential or broaden the allowlist. The relay remains CONNECT-only.

`{ mode: "none" }` is fail-closed: it never invokes the resolver and never
issues an endpoint, token, or lease.

The returned token is stored only as a SHA-256 digest. Tokens are never reused
during a service lifetime. `summarizeWorkspaceEgressLease` redacts both the
credential and relay endpoint for logging.

## Example resolver shape

```ts
import { WorkspaceEgressService } from '@sciforge/workspace-egress'

const egress = new WorkspaceEgressService({
  routeResolver: {
    async resolve({ workspaceId, selection, signal }) {
      // The owning host integration selects or creates the appropriate
      // transport. It must not return its SSH credentials or endpoint.
      return createOpaqueRoute({ workspaceId, selection, signal })
    }
  }
})

const lease = await egress.acquireLease({
  workspaceId: 'gpu-workspace-session',
  selection: {
    mode: 'remote-target',
    authorizedSessionId: 'cpu-workspace-session',
    allowlist: {
      rules: [
        { host: 'api.openai.com', ports: [443] }
      ]
    }
  }
})
```

The service rejects non-loopback bind hosts, regular HTTP proxy requests,
missing or invalid tokens, cross-workspace lease operations, unallowlisted
destinations, expired leases, and unavailable routes.

## Scoped local Model Router bridge

`WorkspaceEgressService` also owns the restricted bridge used by a remote
Codex runtime to call the Desktop Model Router. This is not another egress
selection and does not accept an allowlist or remote target:

```ts
const bridge = await egress.acquireModelRouterBridge({
  workspaceId: 'gpu-workspace-session',
  upstreamBaseUrl: 'http://127.0.0.1:3892/v1',
  runtimeKey: localStaticRuntimeKey,
  ttlMs: 60_000
}, {
  routeSignal: sshReverseForwardSignal
})
```

The result contains:

- `endpoint: { protocol: "http", host, port, basePath: "/v1" }`;
- `authorization: { scheme: "bearer", token }`;
- `leaseId`, `workspaceId`, `issuedAt`, and `expiresAt`.

The static Model Router runtime key is retained only in the Desktop process
while the lease is active. It is never returned, persisted, logged, included in
SSH arguments, or sent to the remote Workspace Host. The bridge timing-safely
validates the scoped token, removes remote authorization, proxy, cookie,
forwarding, and hop-by-hop headers, then locally injects the static Bearer key.

Only exact Model Router API method/path pairs are accepted. CONNECT, protocol
upgrade, absolute-form request targets, management endpoints, wildcard routes,
oversized headers/bodies, and excess concurrent requests fail closed. Query and
request body streams are preserved, and Responses API SSE is streamed back
without buffering while response hop-by-hop and cookie headers are removed.

Use `heartbeatModelRouterBridge` to renew the lease and re-probe authenticated
local Router capabilities. Use `revokeModelRouterBridge` on disconnect. Expiry,
an aborted `routeSignal`, a failed heartbeat, or local connection loss revokes
the lease and destroys active streams. `WorkspaceEgressService.close()` and
`sweepExpired()` cover both general egress and Model Router bridge leases.

Remote SSH must expose the returned local bridge port through a separate
loopback-only `ssh -R`. It constructs the remote base URL as
`http://127.0.0.1:<remote-port>/v1` and sends only that URL, the scoped token,
and expiry through the sensitive Workspace Host handshake/control path.
