SciForge 模型选择改版

范围：输入框里的执行环境、模型、思考档位选择，以及背后的 Model Router 和三个 Agent Runtime 接入。基于 main 分支 c8efe61a 的代码阅读和 10-22 故障排查结果。修订（同日二轮）：档位信息改三态（已知支持 / 已知不支持 / 未知）、增加档位翻译表与报错规则、能力表改为种子表 + 动态现查 + 报错纠偏的自动保鲜。

一句话：界面上的模型列表和思考档位不是真实上游模型的能力，而是几处代码写死的默认值。10-22 全部调用失败，就是这条链路的直接后果。

建议：执行环境由用户在新建会话时手选；模型只列真实接入的模型；思考档位只列这个模型声明过的档位，没声明就不发送，交给上游默认。不提供“自动推理档位”。

顺序：先做一个很小的止血改动（停止发送编出来的档位），再做身份显示、Router 模型列表和界面改版。

1. 几个概念

程序的 runtime：代码运行的环境，负责内存、事件循环、系统调用。例如 Node.js、Chromium、JVM。

Agent 的 runtime：负责“跑 agent 循环”的程序。它收到用户消息后调用模型，解析模型要调用的工具，检查权限后执行工具，把结果交回模型，直到这一轮结束；同时管理会话历史、上下文压缩、审批和流式事件。Codex CLI、Claude Code、DSH 都是 agent runtime。模型负责思考，runtime 负责循环和执行。

SciForge 的角色：SciForge 本身没有可选的 agent runtime（代码里的 sciforge ID 已标记废弃，仅为兼容旧数据保留）。它是宿主：托管三个外部 agent runtime，自己负责界面、工具、权限治理、会话记录和模型接入。

Model Router：SciForge 自带的模型网关，夹在 runtime 和真实模型服务之间，负责协议转换和多模态处理。

4. 10-22 故障回顾

测试实例配置的模型是 deepseek-v4-flash-0731，只支持 Chat Completions，没有配置任何思考档位。

事实状态
10-20 14:35（UTC）是最后一次成功的上游调用；从 10-21 17:28（UTC，即北京时间 10-22 01:28）起 18 次调用全部失败，报错为上游拒绝思考档位参数已验证
Codex 两天的轮次记录相同：模型 sciforge-router，未设置档位已验证

Codex 填入了 Router 给的默认 medium，Router 原样转发；上游在这段时间内开始校验这个参数推断（trace 只记录请求体前 4096 字节，看不到实际发送的值）

5. 修改方案

原则

  1. 三个选择各管一件事：执行环境决定谁来跑；模型决定用哪个真实上游模型；思考档位只能从这个模型支持的档位里选。顺序固定为 执行环境 → 模型 → 思考。
  2. 可选档位 = 模型声明的档位 ∩ 当前 runtime 能传递的档位。
  3. 没声明就不发送。模型没有声明档位时，界面显示“上游默认”，请求里不带任何思考参数。只靠这一条，10-22 的故障就不会发生。
  4. 不支持就明确报错。选了模型不支持的档位，在调用上游之前就报 unsupported_reasoning_effort，不悄悄丢弃或替换。
  5. 实际值必须看得见。状态条、用量统计、trace 都显示真实的“runtime · 模型 · 档位”。
  6. 不提供“自动推理档位”。“上游默认”就是诚实的自动：交给上游自己决定，SciForge 不替它填值。

宿主删除三处 medium 默认值（chat-store.ts、app-settings-codex.ts、reasoning-config.ts）；runtime 配置中写入用户选中的真实模型 ID，不再写死别名；用量统计记录真实模型；定时任务显示真实设置
Trace身份和实际发送的档位作为独立字段记录，不再放在会被截断的请求体里。模型 ID 和地址不再抹掉，key 继续隐藏
协作失败信息保留原因，协作界面显示中文说明和原始报错
注意不能只改界面样式。Router 现在只发布一个别名、档位写死，界面选项要真实，必须先完成后端的止血和模型列表改造，否则只是换个样式展示同样的假选项。

6. 实施顺序

1

止血

未声明档位时不发送思考参数；删除宿主和 Router 中写死的档位与默认值；不支持的档位调用前报错。改动小，可以单独发布。
验收：用本地模拟上游重放 10-22 的场景，请求中不带思考参数且调用成功；不调用真实模型。

2

显示真实身份

状态条、用量统计、trace 显示“runtime · 模型 · 档位”；上游错误统一结构并给出中文说明。

3

Router 按声明生成模型列表

真实模型列表、中性档位到各家字段的翻译。开始前需先补契约测试：确认 Codex 收到空档位列表时的行为，以及收到“未知”状态（还没查到能力）时的行为——空列表（确定没有）与未知是两回事，反应可能不同。

4

界面改版

按第 5 节界面方案实现。
验收：源码运行和打包后的应用都要验证，逐个界面截图。

5

模型能力表：自动保鲜

不依赖专人维护，分三层。① 静态种子表：Router 包内置常见模型（DeepSeek、GPT、Claude、Qwen、Kimi、GLM、MiniMax 等）的档位数据，没网也能用，每条标“最后实测日期”，用户可在设置中覆盖。② 动态现查：定期向上游的模型列表接口查询能力声明，结果缓存（约 24 小时），厂商加新档位次日自动生效。③ 报错自动纠偏：上游返回“不支持该档位”时，顺手把该模型档案的档位集合改小，下次不再发错——错误本身就是更新信号。定期探针复测（拿固定小题逐档验证）列为后续可选项，发现实际偏差再补。
