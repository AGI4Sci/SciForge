# Identity and Access

> Current-state audit: 2026-08-22. Local Account selection and the Host-injected `local-selection` Principal remain available for offline work. The `identity-access` domain package also implements system-browser Authorization Code with PKCE, strict OIDC token verification, canonical Cloud User lookup, Desktop Device enrollment, and the `cloud-authenticated` Principal transition. The SciForge Cloud service that supplies `/v1/me` and Device APIs is an external deployment dependency rather than an implementation owned by this repository.

Identity and Access is the SciForge bounded context for recognizing people and establishing who is currently acting. It keeps SciForge identity independent from external services while allowing a user to authorize explicit account bindings.

## Language

**SciForge User**:
A person with one stable identity owned by SciForge. V1 represents the person with a Local Account; Connected Mode uses the canonical identity established through the SciForge cloud identity boundary.
_Avoid_: OpenContent user, provider account, installation ID, window caller, Agent thread

**Canonical SciForge User**:
The cloud-recognized SciForge User used consistently for devices, Agents, Projects, remote Sessions, attribution, and audit. It is established only after unified identity authentication and never inferred from a display name, email address, Local Account, or Zulip Account.
_Avoid_: Zulip user, matching email, cloud username, local user ID

**Canonical User ID**:
An opaque, permanently stable identifier generated by SciForge Cloud for one Canonical SciForge User. It is never derived from an OIDC claim or external account identifier and is never reassigned to another user.
_Avoid_: Keycloak subject, email address, username, Zulip user ID

**OIDC Subject Binding**:
The unique association between a Canonical SciForge User and one immutable Keycloak `issuer + subject` pair. It is authentication evidence, not the user's display identity or authorization role.
_Avoid_: email match, username match, Project membership, Zulip binding

**Desktop OIDC Client**:
The secretless public Keycloak client used only by SciForge Desktop through the system browser and Authorization Code with PKCE. It is distinct from the Zulip client and from any future Cloud Web confidential client.
_Avoid_: shared Zulip client, embedded login page, desktop client secret, Cloud Web client

**Local Account**:
A persistent, application-local representation of a SciForge User with an immutable, randomly generated user ID and a mutable Username. Selecting a Local Account establishes local identity context but does not authenticate the person for remote or cross-user authority.
It is not a privacy or storage-isolation boundary for local application data.
_Avoid_: Local Profile, cloud account, verified identity, guest account, local tenant

**Username**:
The user-chosen display name of a SciForge User. In V1 it is unique only within one SciForge installation and never serves as an identity key or authentication factor.
_Avoid_: user ID, login credential, email address, global handle

**Login Method**:
A means by which a person proves control of a SciForge User. A Login Method authenticates the user but is not itself the user identity.
V1 username selection is not a Login Method because it proves no secret or external factor.
_Avoid_: SciForge User, local account selection, external account binding, provider credential

**Local Identity Session**:
The persisted selection of the current Local Account, restored automatically across application restarts until the user exits it. It carries a local user ID but no credential and no remote authorization.
_Avoid_: cloud session, access token, authenticated session

**Local Mode**:
The offline-first SciForge operating state in which local chat, Workspace, models, and tools remain available without a cloud-authenticated SciForge User. Local Mode grants no remote authority by itself, but its Local Account may own an explicitly enrolled node-local Provider Connection whose external service independently authenticates and authorizes access.
_Avoid_: anonymous cloud user, guest account, shared administrator

**Connected Mode**:
The SciForge operating state backed by a current cloud-authenticated Human Principal. Cloud Projects and cross-user identity authority require Connected Mode; an independently authenticated external Provider Connection does not turn Local Mode into Connected Mode.
_Avoid_: internet available, provider login, Local Profile

**Human Principal**:
The representation of the current SciForge User and the assurance with which that identity was established. Local Account selection can assert `local-selection`. A verified OIDC session mapped through `/v1/me` can assert `cloud-authenticated` only while the current Desktop Device is `ACTIVE`. A Human Principal may own a node-local Provider Connection, but the Provider's own authentication rather than either Principal assurance proves control of the External Account.
_Avoid_: caller ID, installation ID, email match, provider login

**Principal Assurance**:
The evidence class with which Identity and Access established a Human Principal. `local-selection` identifies only the selected Local Account and may scope a separately authenticated node-local Provider Connection; `cloud-authenticated` remains required when SciForge itself asserts remote or cross-user identity authority.
_Avoid_: role, permission, login status boolean

**Identity Migration**:
An explicit, user-confirmed association and bounded reference migration from the currently selected local user ID to a cloud-issued canonical user ID after successful cloud authentication. It preserves the old ID only as a non-authorizing alias, does not reassign installation-local data or rewrite history, and never changes a running Agent turn's captured Principal.
_Avoid_: silent account merge, client-issued cloud user ID, username match

**External Account**:
An account whose identity and lifecycle are owned by a service outside SciForge, such as OpenContent. Its service-native permissions remain authoritative within that service.
_Avoid_: SciForge User, Login Method

**External Account Binding**:
An explicit, revocable association authorized by a SciForge User between that user and one External Account. A binding does not merge the two identities or transfer either system's permissions to the other.
_Avoid_: email match, account merge, shared login

**Zulip Account**:
An External Account owned by one Zulip organization and identified by that organization's stable identity together with its immutable Zulip user ID. It is a communication endpoint, not a SciForge User or a source of Project authority.
_Avoid_: SciForge User, email identity, nickname identity, Human Principal

**Zulip Identity Binding**:
An explicit, revocable association between one Canonical SciForge User and one verified Zulip Account. It proves which communication endpoint belongs to the user but grants no Project membership, Agent ownership, or local execution permission.
_Avoid_: email match, nickname match, shared credential, automatic account merge

**OpenContent Account**:
An External Account owned by OpenContent and used for OpenContent documents, spaces, and collaboration permissions. It is never the source of a SciForge User identity.
_Avoid_: SciForge account, SciForge login, Human Principal

**OpenContent Account Enrollment**:
The explicit node-local binding of one existing OpenContent Account to the current Local Account after OpenContent authenticates the supplied credentials. SciForge does not create the account, infer identity from matching attributes, or transfer Project permissions into OpenContent ACLs.
_Avoid_: SciForge login, account provisioning, account merge, email-based binding

**Device**:
A user-associated endpoint on which SciForge functionality is present. A Device has an explicit kind and does not become a Human Principal or Agent merely by being registered.
_Avoid_: SciForge User, session, Agent

**Agent Host**:
A computer Device capable of running a SciForge Agent and using locally authorized models, tools, data, and network resources. Only an Agent Host can own an Agent execution identity.
_Avoid_: mobile client, Human Principal, cloud coordinator

**Communication Device**:
A mobile Device that delivers SciForge messages and collects Human responses but cannot own or execute an Agent.
_Avoid_: Worker, Agent Host, mobile Agent

**Agent**:
An execution identity owned by one SciForge User and hosted by one Agent Host. An Agent may hold different execution roles in different Projects, but it is never a person or a Device.
_Avoid_: SciForge User, Device, Coordinator product, Worker product
