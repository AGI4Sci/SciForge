# 自动化科研需求记录

最后更新：2026-06-09

本文档用于记录 SciForge 在自动化科研方向的需求。同学们可以在这里提出、补充、认领和更新需求。

目前项目还处在**基础能力建设阶段**。先把通用能力打牢，再逐步支持 AI 研究和 AI + 生物跨学科研究中的专用场景。

## 目标

SciForge 希望帮助研究者把论文、数据、代码、图片、软件操作和实验过程组织成可追踪、可验证、可复用的科研工作流。

重点方向：

- **AI 研究**：论文理解、代码复现、实验运行、benchmark、模型评测、结果分析。
- **AI + 生物**：多模态数据理解、文献证据整理、组学分析、结构/序列/图像理解、实验辅助。

## 需求怎么写

新增需求时，尽量写清楚四件事：

- **要解决什么问题**
- **输入是什么**
- **希望 SciForge 做什么**
- **怎样算完成**

格式可以很轻量：

```markdown
### 需求名称

- 提出者：
- 方向：通用能力 / AI 研究 / AI + 生物
- 阶段：基础能力 / 专用能力 / 端到端场景
- 状态：待讨论 / 待认领 / 进行中 / 已完成

说明：

验收：
```

## 当前基础能力需求

### 1. 支持多模态数据理解

- 提出者：待填写
- 方向：通用能力 / AI + 生物
- 阶段：基础能力
- 状态：待讨论

说明：

SciForge 需要逐步理解常见科研数据和对象，包括文件夹、PDF/论文、表格、图表、显微/医学图像、序列、结构、组学矩阵、通路图、实验表格和研究报告。Agent 不只是把这些内容当成普通文本，而是能识别对象类型、提取关键信息、保留来源，并生成可追踪的解释或分析结果。

验收：

- 能读取至少一种多模态数据对象，并生成结构化摘要。
- 摘要中保留来源、字段含义和不确定信息。
- 后续分析可以引用这次理解结果，而不是重新从零解释。

### 2. 支持图片生成和编辑

- 提出者：待填写
- 方向：通用能力
- 阶段：基础能力
- 状态：待讨论

说明：

SciForge 需要支持科研工作中的图片生成和编辑，例如生成示意图、修改图像标注、制作论文/汇报配图、编辑实验结果截图、生成教学插图等。图片能力应服务科研表达和分析，而不是只做装饰。

验收：

- 能根据文字需求生成一张图片或示意图。
- 能对已有图片做局部编辑、标注或风格调整。
- 生成或编辑结果能作为 artifact 保存，并可被后续任务引用。

### 3. 支持 Computer Use 操纵 VSCode

- 提出者：待填写
- 方向：通用能力 / AI 研究
- 阶段：基础能力
- 状态：待讨论

说明：

SciForge 需要通过 Computer Use 操作真实 VSCode，用于科研代码阅读、修改、运行和调试。这个能力不是另一个独立 agent，而是让 Agent Host 可以观察 VSCode、定位文件和编辑器状态、执行明确的软件操作，并保留操作前后的证据。

验收：

- 能绑定当前 VSCode 窗口并观察文件、编辑器和终端状态。
- 能完成低风险操作，例如打开文件、定位代码、输入文本、保存修改、运行命令。
- 每次操作都有 before/after evidence，方便用户确认结果。

### 4. 支持科学论文与结论可信度校验 skill

- 提出者：待填写
- 方向：通用能力 / AI 研究 / AI + 生物
- 阶段：基础能力
- 状态：待讨论

说明：

SciForge 需要一个用于校验科学论文、实验结果和研究结论可信度的 skill。它可以参考 [academic-integrity-skill](https://github.com/1anj/academic-integrity-skill) 的思路，对论文或结论进行证据化检查，例如图片是否存在复用或异常处理、统计结果是否可疑、方法和数据是否足够支撑结论、引用是否真实相关、是否缺少关键实验或材料。这个能力不应简单输出“真/假”，而应给出风险分级、证据位置和需要人工复核的问题。

验收：

- 能输入一篇论文、报告或一个科研结论，并输出结构化校验结果。
- 能指出支持证据、风险点、缺失信息和建议复核的问题。
- 对高风险判断保留来源位置和理由，避免无证据地下结论。

## 后续可以补充的需求方向

- 论文到实验复现任务包。
- 文献证据矩阵。
- Benchmark 运行与结果对比。
- 组学差异分析辅助。
- 结构、序列、图谱等专用 viewer。
- 需求评论、失败案例和修复任务回流。

## 协作方式

- 想到需求就先写到本文档，不需要一开始就很完整。
- 能写清楚输入、输出和验收的需求，优先进入实现讨论。
- 做需求的同学在对应条目下更新状态、进展和链接。
- 如果需求变大，就拆成更小的基础能力或场景任务。
