# Evidence producer delivery: agent contract and owner audit

## Current acceptance owner

The generated installed composition still includes `@sciforge/domain-evidence-dag/main`. Its native runtime already runs the canonical producer consumer when Evidence enablement is on. Keep that builtin owner canonical for scientific plotting acceptance; do not activate optional DSH Evidence, disable the builtin, share writable store directories, or write receipts manually for this acceptance.

Native delta storage is `userDataDir/evidence-dag/deltas.json`. The optional plugin is granted `EDAG_STORAGE_DIR` or `userDataDir/evidence-dag/python`, hence a different `deltas.json`. A workspace delivery receipt is not proof that both stores contain that delta. The new optional poll refuses existing deliveries whose committed delta is absent from its own store. It does not migrate, copy, re-deliver or pretend it can seal/export those facts. There is no optional background producer timer. This does **not** provide distributed mutual exclusion against an independently active native consumer; production composition must retain one writer owner.

Producer/source digest and workspace/operation idempotency remain canonical. The plugin contains no copied consumer or hand-written delivery receipt.

## Actual agent sequence

1. Produce scientific plotting artifacts in the authorized original Session. The producer writes its pending inbox receipt and must capture that Session's real runtime/thread pair. The workspace alone and a side execution id are not valid substitutes.
2. **Current builtin path:** wait for the native canonical delivery receipt. Invoke public builtin `evidence-dag.snapshot-status`, `evidence-dag.seal-closure`, then `evidence-dag.export-snapshot-products` through the existing capability broker. Do not label this optional DSH Evidence acceptance.
3. **Optional owner-only path:** official native tool `evidence_dag_poll_producer_provenance` accepts `{runtimeId,threadId,workspaceRoot}`. All are required and Host bound. It returns `{delivered,idempotent,skipped,pending:[{producer,fileName,message}],drained}`. A false `drained` or a matching receipt in `pending` is a blocker, not successful delivery. An empty inbox (`delivered=0`) is not evidence that the intended operation was delivered. Other runtime/thread targets are counted as skipped, never read via a private bypass.
4. Read status for the same owner. Require non-null `authoritativeHead.headDigest` and `authoritativeHead.committedWatermark`; take target claim IDs from the actual `provisional.lastGood.claims` projection, not invented IDs. Call `evidence_dag_seal_closure` with `{runtimeId,threadId,workspaceRoot,idempotencyKey,policy:{version:"EvidenceClosurePolicyV1",targetClaimIds:<actual IDs>,expectedHeadDigest:<headDigest>,barrierWatermark:<committedWatermark>,edgeFamilies:[],directions:["inbound"],maxDepth:0,termination:"depth",expandEquivalent:false,expandRefinement:false,cycleHandling:"allow",unknownEdgeHandling:"ignore",requiredRecords:[],requiredExternalRefs:[]}}` for a depth-zero closure; this is not a claim that broader audit requirements are satisfied. If the actual projection has no target claims or has required gaps, do not fabricate a closure. Require `status=complete`, then read status and select **`committed.digest`**, never head/delta/closure digest, as the export Snapshot target.
5. `evidence_dag_export_snapshot_products` takes `{input:{runtimeId,threadId,workspaceRoot,snapshotDigest,idempotencyKey,datacite,targets?}}`. DataCite identity is explicit: `doi,title,creators:[{name,...}],publisher,publicationYear,projectId`; optional discovery fields follow the public schema. For a **new export target**, omit `targets` (or use `{}`), so the canonical Artifact Versions transaction allocates new Artifact/Version identities. For an update only, each named target must carry its real `artifactId` and exact `expectedCurrentVersionId`; do not invent a new artifact id under an update contract.
6. Require five returned product refs and a real `artifact-commit:` transaction identity; verify `snapshotDigest` and exact source refs. Tools return canonical results, not synthesized receipts.

The plugin-owned native tool declaration includes all seven tools and is shipped with the Cordis patch. It describes requested effects; it is not Host approval. The existing builtin IDs deliberately coincide with optional projected IDs, reinforcing that both owners must not be registered as parallel canonical writers.
