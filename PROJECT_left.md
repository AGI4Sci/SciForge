# SciForge Left Pane 任务板

最后更新：2026-06-02

本文档从 [`PROJECT.md`](PROJECT.md) 拆出，单独维护 SciForge 左侧栏 / Cursor-like Agents sidebar / Repositories / Threads / Search / Automations / Customize 的任务和验收规则。

## 当前目标

- 左侧栏必须对齐 Cursor Agent desktop app 的 Agents sidebar：顶部提供 Hide Sidebar、Search、Back/Forward、New Agent、Automations、Customize；主体按 Repositories 分组展示 workspace/project/thread；底部保留账户、设置、状态和 SciForge 特有入口。
- 左侧栏只管理 workspace/project/thread 的可视化投影、选择、排序、归档、置顶、草稿、搜索和上下文入口；真实任务启动、工具选择、repair、sub agent 创建和 workspace 写入仍由 Agent Host 执行并产生 trace。
- SciForge 特有的 Feedback、scientific workflow、capability/skill/MCP、workspace health、local runtime status 可以保留，但必须融入 Cursor-like 信息架构，不能把左栏退化成文件树、日志栏或 provider/debug 面板。

## 不可变规则

- 所有修改必须通用，不能为当前页面、截图、URL、文件名或历史 run 写硬编码补丁。
- 代码路径保持唯一真相源；旧逻辑和最终方案冲突时删除或迁移旧逻辑，不做长期并行实现。
- GUI -> TUI 只发送终端等价文本、focus/confirmation 结果或只读 projection；TUI -> GUI 只通过 declared GUI intents。
- 左侧栏不得执行 workspace 写入、provider route、capability ranking、Computer Use action、repair 或 sub agent 创建；需要副作用时只发 Agent Host command / declared intent。
- 大 payload、截图、录屏、terminal transcript、DOM snapshot、artifact、audit 和 replay 必须 refs-first；不得内联 raw screenshot/base64/provider payload/secret。
- 涉及 provider URL、API key、model name、Authorization、token、secret、password、credential 的日志和 evidence 必须脱敏；ignored local config 不得提交。
- 业务代码单文件超过约 2000 行时必须拆分或登记拆分任务。
- 已完成 TODO 需要打勾，并补充日期、evidence refs、验证命令和最终状态。

## 模块化设计原则

- 公共函数只有四个：`module.describe`、`module.query`、`module.read`、`module.invoke`。
- `describe/query/read` 必须只读；只有 `invoke` 可以有副作用。未声明 module function、intent、facet 或 ref prefix 必须 fail closed。
- `list/search` 收敛为 `query`，`stat` 收敛为 `read({ includeMeta: true })`，`watch/subscribe/present/ask_user/apply_batch` 收敛为具体 `invoke` intent。
- Agent Host 负责编排 semantic pipeline；模块不得直接 import 或调用其它模块；GUI 可以展示 pipeline trace，但不决定 pipeline。
- trace-first 是默认要求：跨模块组合必须记录 step id、moduleId、function、intent/query/ref、input/result summary、refs、approval、operation、timing、status 和 parent/child relation。

## 体验对齐原则

- 左侧栏体验对齐必须反复、深度使用 SciForge web 和 Cursor Agent desktop app 双端验证：每轮实现前观察 Cursor 的稳定行为，每轮实现后在 SciForge 中完成同类真实 workflow，并把差异沉淀为通用规则和测试，不以一次性截图/坐标/会话作为结论。
- 左侧栏首屏必须是 Cursor Agent 的 Agents sidebar 模型，而不是 IDE 文件树：New Agent、Automations、Customize、Repositories、project groups、thread rows、See more、account/settings/status 是稳定结构。
- 搜索必须像 Cursor command palette 一样统一查找 files、actions、agents、modes、models、skills、MCP servers 和 threads；搜索结果只展示公共标题/摘要，不泄露本地绝对路径、provider、token 或 raw runtime 字段。
- Repositories 分组必须支持 current workspace、peer workspace、Home/default workspace、Open Workspace、Customize Sidebar、每个 project 的 New Agent 和 See more；project 切换只改变 presentation/selection，真实 workspace 激活走 Agent Host command。
- Thread row 必须展示状态图标、标题、相对更新时间和行内动作；done/running/failed/blocked/draft/archived/discarded/pinned 都必须有 typed state。已完成 thread 默认 Archive；draft thread 默认 Discard；archived/discarded 只能 Restore。
- Pin/Archive/Discard/Restore/Remove/Open Workspace/New Agent 等会改变持久状态的动作必须有 terminal-equivalent commandText 或 declared invoke intent；select/sort/show more/customize visible sections 只能是 local presentation。
- SciForge 特有的 Feedback、scientific scenario、runtime health、workspace diagnostics、capability/skill/MCP 入口可以保留，但必须出现在 Cursor-like sidebar 的 action/search/settings 语义下，不能成为左栏并列的内部 debug 区块。
